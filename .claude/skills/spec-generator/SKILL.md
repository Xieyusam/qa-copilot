# Spec Generator (子任务/MVP文档生成器)

这个 Skill 用于在 `.claude/specs/` 目录下生成符合项目 Spec 驱动开发规范的子任务（MVP）文档。

## 执行流程

当你被调用时，必须**严格按照以下步骤交互式地**与用户协作：

### 第一步：需求收集 (Gather Information)
1. 首先，向用户询问以下两个关键信息：
   - **MVP 的名称/英文标识**（将作为 `.claude/specs/<MVP_Name>` 的文件夹名，例如 `user-auth`）。
   - **核心需求和业务目标**（这个 MVP 需要实现什么功能？）。
2. **停止输出**，等待用户回复。

### 第二步：生成 `requirements.md` (需求文档)
获取到用户回复后，分析需求并生成 `.claude/specs/<MVP_Name>/requirements.md` 文件。
**格式要求：**
- `# 需求文档`
- `## 简介`：简述该 MVP 的目标和主要功能。
- `## 词汇表`：列出该 MVP 涉及的领域专属词汇、系统组件名称及其解释。
- `## 需求`：按模块或功能拆分需求。每个需求包含：
  - `### 需求 X：<需求名称>`
  - `**用户故事：** 作为一名...我希望...以便...`
  - `#### 验收标准`：使用有序列表，每条标准必须使用 `THE System SHALL...` / `WHEN...` / `IF... THEN...` 这种形式进行严谨描述。

完成 `requirements.md` 后，向用户展示生成的结果，并询问是否可以直接进入技术设计阶段，或需要进行修改。**停止输出**，等待确认。

### 第三步：生成 `design.md` (技术设计文档)
向用户确认需求文档无误后，生成 `.claude/specs/<MVP_Name>/design.md` 文件。
**格式要求：**
- `# 技术设计文档：<MVP_Name>`
- `## Overview`：技术栈概述。
- `## Architecture`：系统架构说明，**必须包含一个 Mermaid `graph TB` 流程图或架构图**。
- `## Components and Interfaces`：定义核心前后端组件和 API 接口（如 RESTful 路由、Vue 组件树、数据模型）。

完成 `design.md` 后，向用户展示生成的结果，并询问是否可以直接进入任务拆解阶段，或需要进行修改。**停止输出**，等待确认。

### 第四步：生成 `tasks.md` (任务拆解文档)
向用户确认设计文档无误后，生成 `.claude/specs/<MVP_Name>/tasks.md` 文件。
**格式要求：**
- `# 实现计划：<MVP_Name>`
- `## 概述`：一句话总结实现目标。
- `## 任务`：将开发工作拆解为可执行的 Todo 列表。
  - 使用 `- [ ] 1. <主任务>` 的形式。
  - 主任务下包含子任务，如 `- [ ] 1.1 <子任务>`。
  - **必须**在每个主任务或子任务的末尾，用斜体标明关联的需求，例如：`_需求：1.1, 2.1_`。

完成 `tasks.md` 后，通知用户子任务规格文档已全部就绪。

## 注意事项
- **必须一步一步交互生成**，不要一次性生成所有三个文件。
- 确保所有输出语言为**中文**。
- 严格遵循本文档中定义的结构规范，不可遗漏词汇表、验收标准特定语法、Mermaid 图表和需求映射等关键元素。
