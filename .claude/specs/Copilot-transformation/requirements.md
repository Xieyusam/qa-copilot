# 需求文档：Copilot-transformation

## 简介
本项目旨在将现有的内部知识库应用升级为一个支持多意图识别和工具调用的 AI-Copilot 助手。本次 MVP 将重构核心工作流，引入多场景路由能力（知识库问答、日志分析、文本翻译、Jira 工具调用），全面优化前端对话体验（支持流式中断、重新生成及性能优化），并大幅提升文档检索的精准度与可视化效果。

## 词汇表
- **LangGraph**：用于编排 LLM 代理（Agent）工作流的框架，支持定义状态图（State Graph）和循环/路由逻辑。
- **意图路由 (Intent Routing)**：在对话初期，通过 LLM 或规则判断用户的提问目的，从而将请求分发给不同处理节点的能力。
- **Semantic Chunking (语义切分)**：一种基于文档结构（如 Markdown 标题、段落换行符）进行文本分块的方法，以保持切分后的上下文语义完整。
- **混合检索 (Hybrid Search)**：结合向量检索（如 ChromaDB）和传统关键词倒排索引（如 BM25）的检索方式。
- **重排 (Reranking)**：对初步检索出的文档片段（Top-K）进行二次打分和排序，以提高最终召回内容的质量。

## 需求

### 需求 1：工作流与多意图路由
**用户故事：** 作为一名内部员工，我希望助手不仅能回答知识库问题，还能帮我分析日志、翻译文本或查询 Jira 任务，以便我在一个窗口完成多种工作。
#### 验收标准
1. THE System SHALL 基于 LangGraph 重构当前 RAG 工作流，增加“意图识别”节点。
2. WHEN 用户输入内容，THE System SHALL 将其路由到以下四个分支之一：
   - **知识库问答**：执行现有的 RAG 流程。
   - **日志分析**：调用指定的日志分析 Prompt/节点。
   - **文本翻译**：调用指定的翻译 Prompt/节点。
   - **Jira 工具调用**：调用 Mock 的 Jira API 获取任务状态并返回。

### 需求 2：前端交互体验优化
**用户故事：** 作为一名用户，我希望在助手生成超长回答时浏览器不会卡顿，并且我能随时打断生成或要求它重新生成，以便更好地控制对话节奏。
#### 验收标准
1. THE System SHALL 在前端实现基于 `AbortController` 的流式响应中断功能，允许用户点击“停止生成”按钮立即终止 SSE 连接。
2. THE System SHALL 在每条历史消息旁提供“重新生成”按钮，点击后清除该消息及之后的历史，并以该用户问题重新发起请求。
3. THE System SHALL 优化 `MessageBubble.vue` 中的 Markdown 渲染逻辑，采用增量解析或防抖策略，确保长文本流式输出时页面滚动和输入不卡顿。

### 需求 3：检索增强与可视化
**用户故事：** 作为一名知识库使用者，我希望能看到检索出的文档片段的具体相似度得分，以便我判断系统回答的可靠性。
#### 验收标准
1. THE System SHALL 在后端的 ChromaDB 检索接口中，计算并返回 Top-K 结果的相似度得分（Similarity Score）。
2. THE System SHALL 在前端对话气泡的“来源”列表（Sources）中，将相似度得分可视化展示（例如以百分比或分数形式）。

### 需求 4：文档语义切分优化
**用户故事：** 作为一名知识库管理员，我希望系统能更智能地切分上传的文档（特别是 Markdown、Word 和 Excel），以便检索时不会出现句子断裂或表格数据丢失的情况。
#### 验收标准
1. WHEN 上传的文件类型为 `.md`，THE System SHALL 采用基于 Markdown 标题层级的切分策略。
2. WHEN 上传的文件类型为 `.txt`、`.docx` 或 `.pdf`，THE System SHALL 采用基于段落和标点符号的递归字符切分策略（优先按 `\n\n` 切分）。
3. WHEN 上传的文件类型为 `.xlsx`，THE System SHALL 采用“表头-行值对”展开策略，将 Excel 每一行数据转化为带有完整表头上下文的独立文本段落，以最大化向量检索的准确度。

### 需求 5：混合检索与重排 (Reranking)
**用户故事：** 作为一名用户，我希望搜索特定专业术语或错误码时，系统也能精准召回包含这些词汇的文档，从而提高问答的准确率。
#### 验收标准
1. THE System SHALL 在后端引入 BM25 算法实现关键词倒排索引。
2. WHEN 执行知识库问答路由时，THE System SHALL 并行执行向量检索和 BM25 检索，并合并结果。
3. THE System SHALL 引入 RRF (Reciprocal Rank Fusion) 倒数秩融合算法对合并后的结果进行极速二次打分排序。
4. THE System SHALL 支持配置独立厂商的 Embedding API（兼容 OpenAI 格式），以替换本地低效模型，加速向量计算过程。

### 需求 6：文档解析进度实时反馈
**用户故事：** 作为一名知识库管理员，我希望在上传文档后能直观地看到它的解析和入库进度，而不是只能被动等待。
#### 验收标准
1. THE System SHALL 提供一个文档状态查询接口或机制。
2. THE System SHALL 在前端“文档列表”页面实时（或通过轮询）更新文档的状态（如：排队中、解析中、切分中、已完成、失败）。

### 需求 7：底层 AI 框架架构升级
**用户故事：** 作为一名开发人员，我希望项目使用最新的 LangChain 和 LangGraph 版本，以便利用最新的特性和性能优化，同时保持生态的健壮性。
#### 验收标准
1. THE System SHALL 将 `langchain` 及其配套库（如 `langchain-community`, `langchain-openai` 等）升级到 1.0.0 以上版本。
2. THE System SHALL 将 `langgraph` 升级到 1.0.0 以上版本。
3. THE System SHALL 确保所有现有的工作流和集成（如向量检索、路由节点）在升级后通过所有自动化单元测试。
