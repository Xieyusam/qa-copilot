# QA Copilot MVP5 - 需求文档

## 1. 项目概述

MVP5 聚焦于**可观测性建设**、**多模态增强**、**数据源扩展**和**切分策略优化**，提升系统成熟度。

### 背景

MVP4 完成了知识库分类管理和前端设计规范，但存在以下问题：
1. **可观测性不足**：日志无结构化、无 trace 串联、无 metrics、无查询界面
2. **多模态能力缺失**：仅支持文字对话，无文件上传处理、无摘要/报表生成工具
3. **数据源单一**：仅支持本地上传，无外部数据源集成
4. **切分策略混乱**：按文件格式硬编码策略，用户无法自定义

### 目标

- 构建完整的可观测性栈（结构化日志 + trace + metrics + 日志查询）
- 增强多模态对话能力（上传 + 摘要 + HTML 报表）
- 扩展数据源（飞书文档拉取）
- 重构切分策略为可配置模式

### 2.4 文档切分配置

#### 2.4.1 重构原因

**现状问题**：chunker.py 中硬编码 `md→markdown`、`xlsx→excel`、`other→text`，用户无法自定义不同文件格式的切分策略。

#### 2.4.2 可配置切分策略（6种）

| 策略 | 原理 | 适用格式 | max_tokens | overlap |
|------|------|---------|------------|---------|
| `recursive_text` | 递归字符切分，separator 列表递进切分 | txt/md/docx（通用，默认） | ✅ | ✅（按句子边界） |
| `semantic` | **基于 Embedder 计算 embedding 相似度**，语义段落边界检测 | PDF/长文档 | ✅ | ✅（按语义边界） |
| `sentence` | 正则按标点（。！？.?!）切分 | FAQ/聊天记录 | ✅ | ✅（按句子边界） |
| `sliding_window` | 固定 token 数滑动窗口，步长 = max_tokens - overlap | 强上下文连贯性 | ✅ | ✅（固定 token） |
| `markdown` | MarkdownHeaderTextSplitter 保留标题层级 + token 二次切分 | md | ✅ | ✅（按 header 块） |
| `excel` | 按 `\n\n` / `\n` 切分，不破坏单元格行结构 | xlsx/xls | ✅ | ✅（按行/块） |

**语义切分（semantic）真实实现逻辑**：
1. 用标点将文本拆分为候选句子
2. 将连续句子合并为候选 chunk（不超过 max_tokens）
3. 对每个 chunk 调用 `Embedder.embed([chunk])` 获取向量
4. 计算连续 chunk 之间的余弦相似度
5. 当相似度突然下降 > 阈值（如 0.3）时，断开作为新的语义段落
6. overlap：保留上一个 chunk 的最后 1-2 个句子到下一个 chunk

#### 2.4.3 配置模型

- 每个分类独立配置切分策略
- 支持按文件格式覆盖默认策略（JSONB）
- 可配置参数：`max_tokens`（默认512）、`overlap`（默认50）

#### 2.4.4 智能推荐策略（按文件类型）

| 文件格式 | 推荐策略 | 说明 |
|----------|---------|------|
| pdf | semantic | 基于语义边界，保持段落完整性 |
| md / markdown | markdown | 保留标题层级结构 |
| docx / txt | recursive_text | 通用递归切分 |
| xlsx / xls | excel | 保持表格行结构 |

**前端交互**：上传时根据文件类型自动推荐策略，用户可手动切换覆盖。

### 2.5 数据清洗模块

#### 2.5.1 清洗流水线

| 步骤 | 功能 |
|------|------|
| HTML 去除 | BeautifulSoup 去除标签、script、style、HTML 实体 |
| 特殊字符过滤 | 零宽字符（\u200b\u200c\u200d）、控制字符 |
| 空白标准化 | 多空格→单空格，多换行→双换行 |
| 噪声行过滤 | 过滤纯数字行、过短无意义行 |

#### 2.5.2 集成位置

```
parser.parse() → DocumentCleaner().clean() → chunker.chunk() → embedder.embed() → vector_store.add_chunks()
```

### 2.6 前端知识库页面改造

#### 2.6.1 两级导航

| 层级 | 视图 | 内容 |
|------|------|------|
| 第一层 | 分类列表 | 显示所有分类（名称、描述、文档数） |
| 第二层 | 文档列表 | 点击分类后，展示该分类下文档列表 + 统一上传入口 |

#### 2.6.2 统一上传面板

- **位置**：二级视图（文档列表页 header）
- **形式**：卡片式 Tab 切换
- **Tab 1 - 本地上传**：拖拽文件 + 分片策略选择（按文件类型推荐 + 可手动覆盖）+ max_tokens + overlap + 文件大小限制 100MB
- **Tab 2 - 飞书链接**：URL 输入 + 标题/类型（手动） + 定时更新策略
- **分片策略**：按文件类型自动推荐（md→markdown、xlsx→excel、pdf→semantic、docx/txt→recursive_text），用户可手动切换
- **目标分类**：自动使用当前所在分类，无需用户选择
- **飞书按钮**：只在二级视图显示，自动填入当前分类 ID

#### 2.6.3 异步上传确认流程

**现状**：选择文件后立即上传，同步处理，页面等待。

**改造后**：
1. 用户选择文件 → 本地预览文件名（不调 API）
2. 点击「确定」→ 调 API 创建文档记录（status=pending）
3. 后端后台异步处理（解析 → 清洗 → 切分 → 向量存储）
4. 前端显示「处理中」状态，文档列表轮询或即时更新
5. 处理完成后文档显示「就绪」

#### 2.6.4 分类管理

- **一级视图分类卡片**：每个分类卡片提供「编辑」「删除」图标按钮
- **编辑弹窗**（CategoryManager）：
  - 名称输入
  - 描述输入
  - 分片策略配置（**仅编辑时显示**，新建时不显示）
  - **删除按钮**：红色危险操作，点击后弹出确认框
- **新建分类**：只有名称 + 描述，无分片策略

#### 2.6.5 交互说明

- 分类列表保留（一级视图），卡片上显示编辑/删除按钮
- 点击分类后进入二级视图（文档列表）
- 切换分类可返回一级
- 新建分类**不包含**分片策略（分片策略在上传时配置）
- 整体布局保持列表模式

## 5. 约束与假设

### 约束

- 不引入新的 UI 库，基于现有 Tailwind CSS
- 飞书 API 具体调用在调研后实现，当前为框架
- 日志查询 API 读取日志文件，不接入 ELK 等外部系统

### 假设

- 日志文件数量上限可控（10 个 × 100MB = 1GB 最大）
- APScheduler 与 FastAPI 异步生态兼容良好
